# LA-LagCheck 0.5.0

LA-LagCheck estimates laser/MS time-coordinate drift from block lags, checks whether a single time-axis correction is supported, and exports a separately verified laser log. When the timing checks fail, at the input diagnostic or at the read-back of the written file, `run --export` can still write a provisional corrected log, marked as not verified, using the rate estimated from the acquisition or, if none can be estimated, a reference rate given with `--reference-rate-ppm`. Without either rate, no log is written. It does not change MS intensities or the original input files.

Version 0.5.0 draws `preview_pair.png` and `preview_pair.json` by default for `run` and `wizard`, including unsupported diagnoses and failed read-backs. `--no-preview` explicitly disables drawing. The figure states the input diagnostic, read-back and export stages separately. Published log bytes and their fixed timing mapping take precedence over the current estimated rate; a single-pass baseline is never substituted for an iterated exported log. Without an estimated or user-supplied reference rate, it shows the original or explicitly declared alignment. Missing geometry uses line order and time; diagonal or mixed trajectories also use this nonspatial view. No interval coverage produces a raw signal timeline. Oversized grids use a recorded larger pixel pitch and average contributing intervals; they are inspection previews, not full-resolution images.

When starting alignment is not declared, an unidentifiable automatic start can trigger a separate retry at the original input placement. An automatic rate that fails block agreement or held-out prediction (including their iteration-stage checks) also triggers this retry. It uses the same signal and settings, setting the input-placement offset to zero, with each fragment's original origin shift retained. The candidate is adopted only with a finite rate, positive time scale, and explicitly passing agreement and prediction at both initial-fit and iteration stages. Convergence is reported but is not an additional adoption gate. Top-level strict diagnostic fields stay unchanged; the candidate is recorded under `alignment_fallback` and in `alignment_fallback_report.json` and its block files. Adoption is always provisional, even if read-back passes, and exits 2. Adopted candidates take precedence over the original estimate and a reference rate. A rejected retry retains the original candidate or reference under the existing rules and records its rejection. `--no-alignment-fallback` disables retry; `--no-provisional` disables retry and provisional logs; `--no-preview` only disables drawing. Without `--export`, retry can still supply a preview but no log. See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for the input-placement assumption and explicit next steps.

The default run reader excludes exactly zero-duration firing pairs from analysis and records their original 1-based CSV data-record numbers in `input_processing.json`. Negative durations, overlapping or incomplete events remain errors. Original files are read-only. Excluded zero-duration event rows remain in any timestamp-corrected CSV; `output_config.zero_duration_policy=exclude` makes the program's read-back apply the same exclusion. This is not a claim that another importer treats those rows identically.

For the generic laser-state adapter, disconnected selected-sample or sequence fragments are diagnosed separately under `segment_001/`, etc., with a `segments.json` index and a root raw-signal overview. No gap is bridged and no logs are combined. The original MS time axis is retained; a declared offset is adjusted by each fragment's recorded origin shift. A fragment containing only Off metadata is recorded as `no_firing_fragment`, without inventing another tissue image. Multiple samples require an exact selector in that generic adapter. The explicit New Wave adapter instead interprets Sequence Number as a line/spot identifier. Its exact named-sample selection can omit interleaved standards within the explicitly paired input file, retaining source gaps and original firing times without combining firing intervals. New Wave sample_scope=all explicitly includes all labels; neither mode invokes the generic per-sequence splitting rule.

`original_input_check` records whether the original records required processing; `processed_input_diagnostic_status` records the unchanged estimator's result on the retained fragment. When exclusion or segmentation was required, a supported processed result has status `processed_input_diagnostic_supported` and can publish only a provisional log (exit 2). It does not upgrade the original input to verified. Clean original inputs retain the two-stage verified export. The reference correlation core and fixed-mapping verification module are unchanged from the frozen 0.4.0 input package. A separate conditional short-acquisition path wraps the standard estimator; the MS reader now recognizes documented comma-filled MassHunter footer padding, and the explicit New Wave reader preserves line/spot event semantics. Standard long-acquisition numerical behavior is checked against the grating example.

An explicitly mapped numeric MS CSV that fails the strict reader because of missing signal values can still receive a raw inspection timeline. Finite values are drawn, nonfinite regions remain gaps, and original record numbers are listed in `input_processing.json`. No rows are removed for diagnosis: the run remains an input error (exit 1, INCOMPLETE) and cannot publish a correction. Unknown mappings or invalid time coordinates are not guessed.

Input or published-byte changes remain integrity errors: exit 1 and `INCOMPLETE.json` invalidate the run. A drawing failure also returns 1 and writes `preview_error.json`; when unchanged original MS data remain readable it supplies a clearly labelled raw-signal fallback. That fallback is not a successful corrected reconstruction.

The package contains raw-data readers, the block-lag estimator, acquisition-level diagnostic checks, corrected-log export and readback, iolite ESL formatting, and a default visual inspection output. Passing the checks describes internal timing evidence; it does not establish independent spatial accuracy or identify the physical cause of drift. The program does not launch iolite or HDIP.

See [QUICKSTART.md](QUICKSTART.md) for synthetic examples, [the chromium-grating example](examples/chromium_grating/README.md) for timing analysis, and [the anonymous R01 example](examples/R01/README.md) for Figure 3 reconstruction and the post hoc Fe56 analysis. [Study summary tables](study_summaries/README.md) cover all 29 acquisitions. Run commands from this package directory using the same Python interpreter:

```text
python -X utf8 -m pip install -r requirements-reference.txt
python -B -X utf8 -m lagcheck --version
python -B -X utf8 -m unittest discover -s tests -v
python -B -X utf8 scripts/verify_package.py
```

The tested environment is Python 3.12.7, NumPy 1.26.4, pandas 2.2.2, SciPy 1.13.1 and matplotlib 3.9.2. The wider dependency ranges in `pyproject.toml` are not a claim that every combination was tested. Matplotlib 3.9.2 is included in the pinned reference requirements and is a default installation dependency (minimum 3.8). One optional private-reference test is skipped when its authorized external fixture is absent; the public tests and grating example do not require it.

Keep generated results outside the package. `FILES.json` records release-file SHA256 hashes, excluding itself; `scripts/verify_package.py` checks those recorded bytes, not scientific validity or receiving-application behavior. See [IMPORTER_CHECK_INPUTS.md](IMPORTER_CHECK_INPUTS.md) before image reconstruction.

New Wave line/spot logs and conditional short-record analysis are described in [NEW_WAVE.md](NEW_WAVE.md), including explicit sample selection, original-coordinate views, unavailable checks and provisional saved-log readback.

The optional iolite-compatible ESL export preserves coordinate, laser-state, speed and other non-attribution cells. When required, it explicitly writes inherited sample/sequence attribution into blank metadata cells, with a source-record audit. Zero-duration On/Off pairs already excluded by the source analysis may be omitted from the compatible CSV; their complete original rows are saved in `excluded_zero_duration_records.json`, without assigning positive durations. This compatibility conversion is distinct from the canonical timestamp-only export. Receiving-application GUI import remains untested.
